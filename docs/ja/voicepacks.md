# ボイスパック

エンジニアが人間のように聞こえるのは、人間の録音を持っているときだけです。ボイス
パックとはそれのことで、フレーズごとに 1 つの WAV ファイルが入ったフォルダーを指
します。エンジニアは Windows の音声合成で話す代わりに、それを再生します。

パックに入っていないもの — あなたの名前、ラップタイム、聞いたことのないドライバー
名 — は、これまでどおり Windows の声で話されます。パックは完成していなくても、持
っている価値があります。

## 手に入れる三つの方法

**公開されているものを導入する。** *設定 → ボイス* に、ダウンロードできるパック
が一覧で出ます。導入前にチェックサムを検証してから展開します。自分以外の言語の
パックを手に入れるならこの方法です。

**自分で録音する**、ウィンドウの中で。上限のない方法で、アプリはこちらを中心に作
られています。*設定 → ボイス → ボイスモデルを作成*。

**Piper でベースを生成する**。オフラインで作り、気になる部分だけ後から録り直しま
す。すぐに正確で聞き心地のよいものが欲しいとき、あるいは走り出す前に 171 のフレー
ズを読み上げたくないときに便利です。

これらは排他的ではありません。導入したパックも Piper のパックもただのパックなの
で、その中のどのフレーズも、後から自分の声に差し替えられます。

### ボイスクローンを使わない理由

これは最初に試して見送った方法です。探しに行く前に、その理由を知っておく価値があ
ります。

このプロジェクトでは、3 分近いきれいな参照音声からクローン音声を生成しました。そ
れをアプリ自身の音声認識にかけ直したところ、「five」はどのテイクも「bye」に、
「four」は「boy」に、「zero」は「yo」になって返ってきました。

原因はフレーズの構成にあります。**171 フレーズのうち 141 が 1 語か 2 語**であり、
短いテキストはクローンモデルが最も苦手とするところです。XTTS は自己回帰的に生成
し、どこで止めるかを自分で決めるため、2 語のフレーズではその判断を縛るものがほと
んどありません。Piper は VITS 系のモデルで、音素から波形まで 1 回の順伝播で進み、
さまよい出るサンプリングのループがありません。違う単語を言うことができないという
性質は、この語彙においては音色よりも重要です。

Crew Chief も同じ問題を同じやり方で解いています。あちらのパックも*録音*であり、
11,176 のドライバー名と 1,052 の数字クリップは人が読み上げたものです。

## 自分で録音する

*設定 → ボイス → ボイスモデルを作成* を選ぶと録音画面が開きます。読むフレー
ズ、カウントダウン、テイク、そして確認のための再生。

聞こえるほどの手間ではありません。全体で **1 フレーズ 3 テイクとして約 40 分**、
しかも途中から再開できます。何回かに分けて進められますし、半分だけ録音したパック
も、保存した瞬間から使えます。

使えるものになるかどうかは、いくつかの点で決まります。

- **口の正面ではなく、少し横に**、指 2 本ぶんほど離して。ブームマイクを息の流れの
  真正面に置くと、*p* や *b* のたびにクリップしますし、クリップは後から取り消せま
  せん。
- **静かな部屋で。** 扇風機や机の下の PC は、すべてのクリップに入り込みます。その
  クリップは、レースの最中にヘッドセットで再生されるものです。
- **距離を一定に。** テイクの合間に身を乗り出したりしないでください。4 種類の距離
  で録られたクリップは、4 人の別人のように聞こえます。
- **Windows のマイクブーストを切る。** あれはコンプレッサーで、単語と単語のあいだ
  で部屋の雑音を持ち上げます。

無線でエンジニアが言うように読んでください。平坦に、急がず、少し退屈そうに。エン
ジニアは演技をしていません。

## Piper でベースを生成する

Piper はオフラインで動き、アプリの中ではなくパッケージングのスクリプトから走りま
す。

```
pip install -r packaging/requirements-voices.txt
python -m piper.download_voices --download-dir models/piper en_GB-alan-medium
python packaging/make_piper_pack.py --name Piper
```

特定のモデルで作るには次のようにします。

```
python packaging/make_piper_pack.py --name Piper --model models/piper/en_GB-alan-medium.onnx
```

**意図的に、オフラインで、アプリの外で。** Piper は CPU でも十分に速いので、発話
のたびに呼びたくなります。しかしそうすると、63MB のモデルと ONNX ランタイムを、直
近 4 回の壊れたリリースがすべてネイティブ依存の取りこぼしだったビルドの中に抱え込
むことになります。パックは WAV の入ったフォルダーにすぎません。ここで生成する分に
は、アプリには何のコストもかからず、ビルドを壊しようもありません。

これは*あなたの*声ではありませんし、そのふりもしません。正確で聞き心地のよいベー
スであり、その上からどのフレーズでもウィンドウの中で録り直せます。

**日本語にはもう一つパッケージが必要で、無いと分かりにくい形で失敗します。**
日本語モデルはテキストを音素に変えるために Piper へ `pyopenjtalk` を要求し、それが
無いとどのフレーズも音声をまったく生成しません。報告されるのは
`wave.Error: # channels not specified` ですが、これは空の出力ファイルであって本当の
原因ではありません。本家の `pyopenjtalk` はソースしか配布しておらず CMake と C++
コンパイラを要求します。`pyopenjtalk-plus` は同じインポート名で wheel を配布する
フォークで、上の依存ファイルに入っています。

## パックの中身

パックはフォルダーで、その中の `voice` サブフォルダーに WAV が入っています。これ
は `crew-chief-autovoicepack` が書き出すのと同じ配置なので、**Crew Chief のパック
はそのまま置けます**。外側のフォルダーが分かれているのは、ライセンスや元の録音を
一緒に置いても、それらがフレーズと取り違えられないようにするためです。

```
voices/
  Norman/
    voice/
      go_ahead.wav
      box_this_lap.wav
      ...
```

WAV のみです。どのジェネレーターも出力する形式であり、標準ライブラリが読める形式
であり、ネイティブ依存と格闘しているビルドにデコーダーを増やさずに済む形式です。

ファイル名はフレーズから作られ、小文字にして、記号は置き換えるのではなく**取り除
きます** — つまり "that's enough" と "thats enough" は同じクリップです。アポスト
ロフィを区切り文字に変えると `that_s_enough` になり、どちらかの綴りで録音したパッ
クが、もう一方を黙って取りこぼすことになります。

## パックの置き場所

**設定 → ボイス** にすべてが並びます。導入済みのもの、同梱のもの、そしてダウンロ
ードできるもの。パックは設定ファイルの隣、`voices/` の中にあり、インストール先の
下ではありません — 更新はインストール先をまるごと置き換えますし、パックはあなた
が自分で置いた大量の音声だからです。**設定 → ボイス → ボイスパックフォルダーを
開く** でそこが開きます。

フォルダーを入れてタブを開き直せば、選択肢に現れます。

## フレーズ一覧

**設定 → ボイス → フレーズ一覧を書き出す** は、エンジニアが言えるすべてのフ
レーズを CSV として、エンジニア自身の言語で書き出します。パックは、それが話される
言語で録音するものだからです。

手で管理するのではなくアプリから生成されるので、エンジニアが実際に言うことと食い
違いようがありません。アプリの外で録音するときや、自分でジェネレーターを書くとき
に使ってください。

## 何も再生されない

**パックが選ばれているか確認する。** *エンジニア → ボイス → ボイス* が、*(パック
なし)* ではなくパックを指している必要があります。

**出力デバイスを確認する。** *オーディオ → 出力* はあなたのヘッドセット、つまりボ
イスチャットで使っているものであるべきで、シムの出力ではありません。

**フレーズが欠けているのは不具合ではありません。** パックにないものは Windows の
声に戻るので、半分だけ録音したパックは、失敗するのではなく 2 人の人物のように聞こ
えます。これは意図したものです。完成する前からパックを使えるようにしているのが、
まさにこの動作です。
