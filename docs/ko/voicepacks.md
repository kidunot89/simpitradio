# 보이스 팩

엔지니어는 사람의 녹음이 있을 때만 사람처럼 들립니다. 보이스 팩이 바로 그것입니다.
문장마다 폴더가 하나씩 있는 WAV 파일 모음으로, 엔지니어가 Windows 음성으로 말하는
대신 이 파일을 재생합니다. 한 문장의 폴더에는 여러 번 녹음한 테이크가 들어갈 수
있고, 엔지니어는 그중 하나를 무작위로 골라 재생하므로 한 스틴트 안에서 같은 콜이
두 번 나와도 기계가 같은 말을 반복하는 것처럼 들리지 않습니다.

팩에 없는 것은 무엇이든 여전히 Windows 음성이 말합니다. 여러분의 이름, 랩 타임,
한 번도 들어본 적 없는 드라이버 이름 같은 것들입니다. 팩은 완성되어야만 쓸모 있는
것이 아닙니다.

## 팩을 얻는 세 가지 방법

**공개된 팩을 설치하세요.** *설정 → 음성*은 내려받을 수 있게 공개된 팩을 나열하고,
요청하면 하나를 설치하되 무엇을 풀기 전에 체크섬을 먼저 확인합니다. 자기 언어가
아닌 언어를 쓰려면 이 길입니다.

**직접 녹음하세요**, 창 안에서. 한계가 없는 길이며, 앱이 그 주위에 지어진 길입니다.
*설정 → 음성 → 음성 모델 만들기*.

**Piper로 기반을 만드세요**, 오프라인으로 만든 뒤, 신경 쓰이는 부분만 다시
녹음합니다. 당장 정확하고 듣기 좋은 것이 필요하거나, 주행 전에 171개 문장을 읽고
싶지 않을 때 쓸모 있습니다.

서로 배타적이지 않습니다. Piper 팩도 평범한 팩이므로, 그 안의 어떤 문장이든 나중에
여러분의 녹음으로 바꿀 수 있습니다.

### 음성 복제를 쓰지 않는 이유

먼저 시도했다가 접었고, 찾아 나서기 전에 그 이유를 알아 둘 가치가 있습니다.

이 프로젝트를 위해 깨끗한 참조 음원 3분 가까이로 복제 음성을 만들었습니다. 앱
자체의 음성 인식기에 다시 넣어 보니 "five"는 모두 "bye"로, "four"는 "boy"로,
"zero"는 "yo"로 돌아왔습니다.

원인은 목록입니다. **171개 문장 가운데 141개가 한두 단어**이고, 짧은 텍스트야말로
복제 모델이 가장 약한 지점입니다. XTTS는 자기회귀적으로 생성하며 언제 멈출지
스스로 정하는데, 두 단어짜리 문장에서는 그 결정을 붙잡아 줄 것이 거의 없습니다.
Piper는 VITS 계열 모델로, 음소에서 파형까지 한 번에 지나가며 헤맬 샘플링 루프가
없습니다. 다른 단어를 말할 수 없고, 이 목록에서는 그것이 음색보다 중요합니다.

Crew Chief도 같은 문제를 같은 방식으로 풉니다. 팩이 *녹음된* 것이고, 드라이버
이름 11,176개와 숫자 클립 1,052개를 사람이 읽었습니다.

## 직접 녹음하기

*설정 → 음성 → 음성 모델 만들기*를 열면 녹음기가 나옵니다. 읽을 문장, 카운트다운,
한 번의 녹음, 그리고 확인용 재생.

들리는 것보다 일이 적습니다. 전체 목록이 **문장당 세 번씩 잡아 약 40분**이고,
이어서 할 수 있으므로 여러 번에 나눠 해도 됩니다. 문장의 절반만 채운 팩도 저장하는
순간부터 동작합니다.

결과가 쓸 만한지는 몇 가지가 결정합니다.

- **입 정면이 아니라 옆으로**, 손가락 두어 개 거리. 붐 마이크를 숨결 한가운데 두면
  *p*와 *b*마다 클리핑되고, 클리핑은 나중에 되돌릴 수 없습니다.
- **조용한 방.** 선풍기나 책상 밑 PC 소리가 모든 클립에 들어가고, 그 클립은 레이스
  도중 헤드셋으로 여러분에게 재생됩니다.
- **일정한 거리.** 녹음 사이에 몸을 이리저리 기울이지 마세요. 네 가지 거리에서
  녹음한 클립은 네 사람처럼 들립니다.
- **Windows의 마이크 부스트를 끄세요.** 그것은 컴프레서이며, 단어 사이의 실내
  소음을 끌어올립니다.

엔지니어가 무전으로 말하듯 읽으세요. 평평하게, 서두르지 않고, 약간 심드렁하게.
엔지니어는 연기하는 것이 아닙니다.

## Piper로 기반 만들기

Piper는 앱 안이 아니라 패키징 스크립트에서 오프라인으로 돕니다. 아래 경로는 소스
체크아웃에서 `apps/client`를 기준으로 한 상대 경로입니다.

```
pip install -r packaging/requirements-voices.txt
python -m piper.download_voices --download-dir models/piper en_GB-alan-medium
python packaging/make_piper_pack.py --name Piper
```

특정 모델로 만들려면:

```
python packaging/make_piper_pack.py --name Piper --model models/piper/en_GB-alan-medium.onnx
```

**의도적으로 오프라인이며 앱 밖입니다.** Piper는 CPU에서도 충분히 빨라서 말하는
시점에 부르고 싶은 유혹이 있습니다. 그러면 63MB 모델과 ONNX 런타임이 빌드 안에
들어가는데, 그 빌드의 최근 망가진 네 번의 릴리스는 모두 수집되지 못한 네이티브
의존성 때문이었습니다. 팩은 WAV 폴더일 뿐이고, 여기서 만들면 앱에 아무 비용도
들지 않으며 빌드를 깨뜨릴 수도 없습니다.

*여러분의* 목소리가 아니며, 그런 척하지도 않습니다. 정확하고 듣기 좋은 기반일
뿐이고, 그 위에 어떤 문장이든 창에서 다시 녹음할 수 있습니다.

**일본어는 패키지가 하나 더 필요하며, 없으면 혼란스럽게 실패합니다.** 일본어
모델은 텍스트를 음소로 바꾸기 위해 Piper에 `pyopenjtalk`를 요구하며, 그것이 없으면
어떤 문구도 오디오를 전혀 만들지 못합니다. 보고되는 것은
`wave.Error: # channels not specified`이지만 이것은 비어 있는 출력 파일이지 진짜
원인이 아닙니다. 원래의 `pyopenjtalk`는 소스만 배포하며 CMake와 C++ 컴파일러를
요구합니다. `pyopenjtalk-plus`는 같은 임포트 이름으로 wheel을 배포하는 포크이며,
위의 요구사항 파일에 들어 있습니다.

## 팩의 생김새

팩은 안에 `voice` 하위 폴더가 있고, 그 안에 문장마다 하나씩 폴더가 있어 그 문장의
테이크들을 담고 있는 구조입니다. `crew-chief-autovoicepack`이 쓰는 배치와 같아서
**Crew Chief 팩을 그대로 넣을 수 있습니다**. 바깥 폴더가 따로 있는 것은 팩이
라이선스와 원본 녹음을 함께 지니면서도 그것들이 문장으로 오인되지 않게 하기
위해서입니다.

```
voices/
  Norman/
    voice/
      pitradio/
        go_ahead/
          1.wav
          2.wav
        box_this_lap/
          1.wav
        ...
```

WAV 파일이 들어 있는 폴더가 곧 문장이므로, `voice`와 그 폴더 사이의 깊이는
자유롭습니다. 레코더는 `pitradio/`를 쓰고, Crew Chief는 카테고리별로 폴더를 씁니다.
어느 쪽이든 같은 방식으로 읽힙니다.

WAV만 씁니다. 모든 생성기가 내놓는 형식이고, 표준 라이브러리가 읽는 형식이며,
이미 네이티브 의존성과 씨름하는 빌드에 디코더를 더 요구하지 않습니다.

폴더 이름은 문장에서 나오며, 소문자로, 문장부호는 대체하지 않고 **버립니다**.
그래서 "that's enough"와 "thats enough"는 같은 클립입니다. 아포스트로피를
구분자로 바꾸면 `that_s_enough`가 되고, 둘 중 한 표기로 녹음한 팩은 다른 쪽을
조용히 놓치게 됩니다.

## 팩이 사는 곳

**설정 → 음성**에 모두 나열됩니다. 설치된 것, 함께 들어 있는 것, 내려받을 수 있는
것. 팩은 설치 폴더 아래가 아니라 설정 옆 `voices/`에 있습니다. 업데이트는 설치
폴더를 통째로 갈아치우고, 팩은 여러분이 직접 넣어 둔 많은 오디오이기 때문입니다.
**설정 → 음성 → 보이스 팩 폴더 열기**로 열립니다.

폴더를 넣고 탭을 다시 열면 선택 목록에 나타납니다.

## 문장 목록

**설정 → 음성 → 문장 목록 쓰기**는 엔지니어가 말할 수 있는 모든 문장을 CSV로,
엔지니어 자신의 언어로 내보냅니다. 팩은 말해질 언어로 녹음하기 때문입니다.

손으로 관리하지 않고 앱에서 생성하므로, 엔지니어가 실제로 말하는 것과 어긋날 수
없습니다. 앱 밖에서 녹음하거나 직접 생성기를 만들 때 쓰세요.

## 아무 소리도 나지 않을 때

**팩이 선택되어 있는지 확인하세요.** *엔지니어 → 음성 → 음성*이 *(팩 없음)*이
아니라 팩을 가리켜야 합니다.

**출력 장치를 확인하세요.** *오디오 → 출력*은 헤드셋이어야 합니다. 음성 채팅에
쓰는 것과 같은 것이며, 시뮬레이터의 출력이 아닙니다.

**문장이 빠진 것은 고장이 아닙니다.** 팩에 없는 것은 Windows 음성으로 넘어가므로,
절반만 녹음된 팩은 실패하는 대신 두 사람처럼 들립니다. 의도한 것입니다. 팩이
완성되기 전부터 쓸 수 있게 하는 것이 바로 그 점입니다.
